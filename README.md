# 箱根ゆる旅プランナー

2026年8月12日〜13日に、小田原駅からレンタカーで箱根を巡る4人家族向けの旅行計画Webアプリです。距離感、混雑の目安、歩く量、訪問順、所要時間を一画面で確認し、無理のない旅程を作ることを目的にしています。

## 実装済み（フェーズ2-Aまで）

- OpenStreetMap + Leaflet の拡大・縮小・移動できる地図
- 小田原・箱根の15地点のマーカーと混雑色分け
- 観光地の詳細パネル（公式サイト、営業時間、料金、駐車場、雨天対応、歩く量、対象年齢、距離など）
- 「予測」と「一般的な傾向」を明確に分けた混雑表示
- 1日目・2日目の旅程追加、削除、上下移動、ドラッグ＆ドロップ並べ替え、日付間移動
- 食事・休憩・宿泊の挿入
- OSRM互換ルーティングによる道路に沿った経路表示。接続不可時は破線の簡易ルートへ自動フォールバック
- 区間を基にした距離・通常時運転時間・混雑考慮時間・滞在時間・終了予定時刻
- 「ゆったり / 標準 / やや忙しい / 詰め込みすぎ」のストレス判定と改善案
- 指定されたA〜Dのサンプル旅程と、7種類の方針からたたき台を選ぶ自動プランUI
- PCの左右レイアウトと、地図を上部に残すモバイルレイアウト

### フェーズ2-A

- 追加先はモーダル内で「日付 → 追加方法 → 必要な場合だけ基準地点」と段階的に選択。おすすめ位置は、全挿入候補の増加運転時間・終了時刻・負荷を比較してから確認付きで適用
- 追加済みの施設は日付を明示し、利用者がチェックして明示した場合のみ別日への重複追加を許可
- 経路表示を「計算中（仮）」「道路経路取得済み」「簡易推計（仮）」に整理。古い経路は即時無効化し、`AbortController` とリクエストIDで競合を防止
- 成功した道路経路は、順序を含むウェイポイントと `driving` をキーにしたメモリキャッシュでセッション中に再利用
- 負荷は日ごとに算出し、旅行全体は高負荷日の影響を重視しつつ宿泊によるリセットを考慮した比較用スコアとして表示
- 観光地一覧に、基準地点を切り替えられる車時間・概算距離を追加

### フェーズ2-B

- 道路経路は区間ごとに取得・キャッシュし、2秒で待機案内、8秒で簡易推計へ切替。簡易推計中は地図から再試行でき、遅れて取得できた道路経路は自動反映
- 8月13日の小田原到着、返却、乗換、概算電車時間、遅延余裕から、東京での夕食に対する通常・混雑・混雑悪化の3ケースを表示
- 観光地一覧に混雑・雨天対応・追加済み日を常時表示し、距離基準と並べ替え条件を切替可能にした
- 追加ダイアログで、追加運転時間・走行距離・終了時刻・負荷・東京到着への影響を、簡易推計で事前確認
- 施設内／駐車場／周辺道路の混雑を分け、9〜17時の予測ヒートマップと根拠を詳細に表示。いずれもリアルタイム情報ではない
- 休憩評価は明示休憩を100%、60分以上の食事を70%、30〜59分の食事を40%、早めの宿到着を一部として扱う
- サンプルプランは距離、運転、日別負荷、東京到着を比較してから確認付きで適用

### フェーズ2-B受け入れ確認

- 負荷スコアは旅程データから毎回再計算し、LocalStorageへスコアを保存しない。配点は画面・ロジックともに `15 / 15 / 10 / 10 / 10 / 10 / 10 / 5 / 10 / 5`
- 帰京予測の電車時間は乗車時間のみの一般的な概算。返却・乗換・遅延余裕は別途加算し、リアルタイム時刻表ではないことを画面に明示
- CIではPlaywright Chromiumを導入し、デスクトップおよび320〜768px幅の操作テストを実行

### フェーズ2-C2-A

- 食事・休憩・自由予定を「予定を追加」ダイアログへ統合。タイトル、日付、滞在時間、追加位置、希望時刻、場所名、メモ、予約済みを指定可能
- 地図地点のない予定は道路ルート・運転時間に加えず、滞在時間と後続時刻のみへ反映
- カスタム予定は同じ旅程配列へ保持するため、ドラッグ並べ替え、上下移動、日付移動、共有URL、印刷、LocalStorageへ既存項目と同様に反映
- 既存の保存データはそのまま復元。不正なカスタム予定だけを除外して正規化する

## 負荷スコアの判定基準

負荷は絶対的な安全判定ではなく、旅程同士を比較するための100点満点の指標です。日ごとに「運転時間（15）・道路混雑（15）・駐車場待ち（10）・観光地数（10）・徒歩量（10）・休憩不足（10）・子どもの疲れ（10）・営業時間の余裕（5）・帰京時刻の余裕（10）・同じ道の往復（5）」を合計します。旅行全体は高い方の日を72%、低い方の日を18%反映し、両日が高負荷の場合のみ連日加算5点を行います。数値、ゲージ、判定ラベル、説明文は同じ区分定義を使います。

| スコア | 判定 |
| --- | --- |
| 0〜25 | かなりゆったり |
| 26〜45 | ゆったり |
| 46〜65 | 標準 |
| 61〜80 | やや忙しい |
| 81〜100 | 詰め込みすぎ |

たとえば66点は **やや忙しい** と表示されます。

## LocalStorageの保存形式

キーは `hakone-yurutabi-planner:v1` です。保存形式は次のとおりです。

```ts
type SavedTripState = {
  version: 1;
  savedAt: string;
  data: TripState;
};
```

読み込み時にはJSON、バージョン、必須項目、時刻、日付、観光地ID、旅程ID、並び順を検証します。順番は日ごとに正規化し、復元できないデータは画面を壊さず初期サンプルプランへ戻して通知します。

## ローカル起動

必要環境: Node.js 20.9 以上、npm 10 以上。

```bash
npm install
cp .env.example .env.local
npm run dev
```

ブラウザで [http://localhost:3000](http://localhost:3000) を開きます。

品質確認:

```bash
npm run typecheck
npm test
npm run build
```

Playwrightの操作テストも用意しています。初回のみブラウザを導入してから実行します。

```bash
npx playwright install chromium
npm run test:e2e
```

## 環境変数・API設定

コピー元は `.env.example` です。

| 変数 | 必須 | 用途 |
| --- | --- | --- |
| `NEXT_PUBLIC_ROUTING_API_URL` | 任意 | ブラウザからアクセス可能なOSRM互換の経路API URL。未指定時は公開OSRMデモサーバーを試行します。 |
| `GOOGLE_MAPS_API_KEY` | 将来用 | Google Maps / Directions を接続する場合のサーバー側キー。現状は未使用。 |
| `MAPBOX_ACCESS_TOKEN` | 将来用 | Mapboxを接続する場合のキー。現状は未使用。 |
| `OPENROUTESERVICE_API_KEY` | 将来用 | OpenRouteServiceを接続する場合のキー。現状は未使用。 |

GitHub PagesではサーバーAPIを実行できないため、経路APIにはブラウザから直接アクセスします。機密情報を `NEXT_PUBLIC_*` に置かないでください。接続に失敗しても、地点を結ぶ破線ルートと安全側の簡易見積もりでアプリを利用できます。

## デプロイ（GitHub Pages）

`main` へのプッシュで `.github/workflows/deploy-pages.yml` が実行され、Next.jsの静的出力フォルダ `out` をGitHub Pagesへ公開します。

1. GitHubリポジトリの **Settings → Pages** を開く。
2. **Build and deployment** の **Source** を **GitHub Actions** に設定する。
3. `main` へプッシュする。Actionsの **Deploy to GitHub Pages** が成功すると公開される。
4. 公開URLは `https://naru18vr.github.io/hakone/`。

GitHub PagesはサーバーAPIを実行できない静的ホスティングです。そのため経路はブラウザからOSRM互換APIへ直接問い合わせ、接続できない場合は破線の簡易ルートに切り替わります。公開OSRMは試作用です。本番では、利用規約・レート制限・可用性を満たすAPIを設定してください。

## 情報の正確性と現時点の制限

- 営業時間、休館日、料金、駐車台数は変更され得るため、アプリでは静的参考データとして扱い、最終確認先として公式URLを明示しています。出発前に必ず公式サイトを確認してください。
- 混雑表示は、8月12〜13日（お盆期）、時刻、天気、場所の一般的な傾向を組み合わせた**予測**か、静的な**一般的傾向**です。リアルタイム渋滞・駐車場満空・人流は表示していません。
- ルートが道路に沿うのはOSRM互換APIに接続できたときだけです。フォールバックは直線を結ぶ参考線で、距離・時間は安全側の推定値です。
- 施設写真はライセンスを確認済みの素材をまだ同梱していないため、詳細パネルは識別用プレースホルダーを表示します。公式提供画像または利用許諾済みCDNへ置き換える前提です。
- 宿泊施設の名称は編集できますが、初期版では座標を「箱根ガラスの森美術館付近」に固定しています。施設検索、住所ジオコーディング、地図ピン指定は未実装です。
- 旅程と旅行条件はこの端末・このブラウザのLocalStorageに自動保存されます。端末をまたぐ保存、共有URL、印刷/PDF出力、会員登録は未実装です。
- Playwrightのブラウザ実行は、実行環境にChromiumを導入できることが前提です。ロジックテストはブラウザなしで実行できます。
